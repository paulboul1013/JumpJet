A

A. 核心原理

一句話答案

VM 能執行 bytecode，因為 compiler 與 VM 對每個 opcode 的數字、operand 格式及 stack effect 有相同定義。

VM 不會重新理解 JavaScript 文法。Compiler 已經把 +、變數、比較與條件分支翻譯成簡單指令。VM 逐一讀取數字，使用 switch 找到對應操作，再修改自己的執行狀態。

B

B. Bytecode program 的組成

  • BytecodeProgram
    • version指令格式版本，目前為 1
    • constantsnumber 與 boolean 常數池
    • codeopcode 與 operand 組成的整數序列
    • slotCount變數儲存空間數量
  • VM 執行狀態
    • instructionPointer下一個要讀取的 code index
    • stack運算用 LIFO stack
    • slots區域變數的 numeric slot
    • initializedSlots防止讀取未初始化 slot

目前的 code 是 JavaScript integer array，不是真正壓縮成 8-bit 的檔案。它在架構上仍是 bytecode，因為每個整數代表 VM 指令或 operand，而不是原始語法。

C

C. Fetch-decode-execute loop

Constant 讀取下一個整數作為 constant index。LoadSlot 與 StoreSlot 把下一個整數當作 slot index。Jump 直接改寫 instruction pointer，因此 VM 能形成條件分支與迴圈。

E

E. Stack machine 為甚麼可行

每個 opcode 都有固定的 stack effect：

Opcode 執行前 執行後
Constant i ... ... value
Add ... left right ... result
Negate ... value ... -value
StoreSlot i ... value ...
LoadSlot i ... ... value
JumpIfFalse address ... condition ...
Return ... value 回傳 value

Binary instruction 會先 pop 右值，再 pop 左值，運算後 push 結果。這個規則讓複雜 expression 能拆成一串小指令，不必在 VM 中保留 AST。

F

F. VM 如何拒絕壞掉的 bytecode

VM 還會拒絕 unknown opcode、未初始化 slot，以及沒有 Return 就結束的程式。這些檢查保護 VM 邊界，但 compiler 仍負責產生語意正確的指令順序。

G

G. 它與真正 CPU 的關係

JumpJet VM 真正 CPU
Opcode 是自訂整數 Opcode 由硬體 ISA 定義
switch 執行指令 電路解碼並執行指令
Stack 與 slots 是 JavaScript array Register 與 memory 是硬體狀態
Instruction pointer 是 JavaScript number Program counter 是 CPU register
執行結果仍由 Node.js 或瀏覽器完成 直接由硬體完成

JumpJet VM 是 interpreter。它用 host JavaScript 模擬一顆簡單的 stack CPU。Bytecode 並不會自行執行，真正執行工作的仍是 execute() 裡的 loop 與每個 opcode handler。
